## 4. Phase 3 — Web User Journey & Draft-to-Render Integrity Audit

### Bugs Identified & Fixed in V2.4.2
1. **P0 — Web Draft API Response Shape vs. `CreateVideoForm` Expectation**:
   - **Root Cause**: `POST /api/lessons/draft` and `GET/PATCH /api/lessons/[lessonId]/draft` previously returned the internal `LessonDraft` object where `lessonPlan`, `mathVerification`, and `narrationPlan` were nested inside `draft.context`, whereas `CreateVideoForm.tsx` read `draft.lessonPlan` and `draft.mathVerification` at the top level.
   - **Fix**: Added `toLessonDraftResponse(draft)` in [`apps/web/src/server/v2-services.ts`](file:///d:/Hackathon/LuminaLearn/apps/web/src/server/v2-services.ts#L62-L75) and wired it into [`apps/web/src/app/api/lessons/draft/route.ts`](file:///d:/Hackathon/LuminaLearn/apps/web/src/app/api/lessons/draft/route.ts) and [`apps/web/src/app/api/lessons/[lessonId]/draft/route.ts`](file:///d:/Hackathon/LuminaLearn/apps/web/src/app/api/lessons/%5BlessonId%5D/draft/route.ts).
2. **P0 — Swallowed Orchestrator Failures on Draft Creation (`unsupported_topic`, `live_mode_unavailable`, `source_evidence_missing`, `mathematical_verification_failed`)**:
   - **Root Cause**: `LessonOrchestrator.orchestrate()` returns a structured `OrchestrationContext` with `stage: 'failed' | 'needs_review'` and `context.error` instead of throwing. Previously, `POST /api/lessons/draft` returned `200 OK` even when `context.lessonPlan` was `undefined`, causing `CreateVideoForm.tsx` to crash when rendering `draft.lessonPlan.title`.
   - **Fix**: [`apps/web/src/app/api/lessons/draft/route.ts`](file:///d:/Hackathon/LuminaLearn/apps/web/src/app/api/lessons/draft/route.ts#L27-L39) now checks `draft.status === 'rejected' || draft.context.stage === 'failed' || draft.context.stage === 'needs_review' || !draft.context.lessonPlan` and returns HTTP `422` with `{ error: code, message, draft: toLessonDraftResponse(draft) }`, surfacing the exact error message in the Web UI.
3. **P1 — Interactive Draft Editing & Re-Verification Before Approval**:
   - **Root Cause**: `CreateVideoForm.tsx` previously displayed a read-only preview and also exposed a legacy direct-render button that bypassed human draft review.
   - **Fix**: Updated [`apps/web/src/components/CreateVideoForm.tsx`](file:///d:/Hackathon/LuminaLearn/apps/web/src/components/CreateVideoForm.tsx#L565-L721) to allow editing `title`, `summary`, `mathematicalClaims` (`statement` and `expectedExpression`), and `narrationPlan.segments` (`text` and `subtitleText`), with a mandatory **"Lưu chỉnh sửa & chạy lại SymPy"** (`PATCH /api/lessons/[lessonId]/draft`) step before the **"✅ Duyệt bản thảo & Render Video Remotion"** button is enabled (`disabled={busy || draftDirty || draft.mathVerification?.status !== 'verified'}`). Removed the direct-render bypass button.
4. **P1 — Ingested Document Persistence Across Server Restarts & Stage Restoration After Failed Edit**:
   - **Fix**: Added `ensureDocumentsLoaded(sourceDocumentIds)` in [`apps/web/src/server/v2-services.ts`](file:///d:/Hackathon/LuminaLearn/apps/web/src/server/v2-services.ts#L54-L60) so `POST /api/lessons/draft` reloads document chunks from `outputs/.documents/<docId>/chunks.json` if the server restarted after upload. Updated [`packages/agent/src/orchestration/draft-manager.ts`](file:///d:/Hackathon/LuminaLearn/packages/agent/src/orchestration/draft-manager.ts#L419-L421) so a draft whose mathematical claim edit fails SymPy and is then corrected on a subsequent edit restores `draft.context.stage` to `'ready_to_render' | 'verified'`.
