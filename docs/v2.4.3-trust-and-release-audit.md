## 1. Executive Summary

LuminaLearn V2.4.3 hardens the V2.4.2 implementation across six critical reliability, mathematical-truthfulness, and security boundaries before live mentor demonstrations on the Gemini API Free Tier:

1. **Gemini Quota & Retry Budget Enforcement (Phase 1):** Eliminates nested retry amplification (`3 × 3 = 9` requests per stage) via a shared per-job `GeminiRequestBudget` (`GEMINI_MAX_REQUESTS_PER_JOB=4`, `GEMINI_TTS_MAX_REQUESTS_PER_JOB=5`) and immediate non-retryable abort on HTTP `401`, `403`, `404`, and `429` (`RESOURCE_EXHAUSTED`).
2. **Mathematical Statement Consistency (Phase 2):** Separates SymPy formal verification of `expectedExpression` from natural-language `statement`, narration `text`, `subtitleText`, and storyboard formulas. Generates a deterministic `canonicalStatement`, classifies `statementVerification` (`formal_match` | `prose_unverified` | `conflict_detected`), blocks contradictory prose/narration/subtitles, and requires explicit teacher semantic confirmation (`humanSemanticReviewConfirmed`) when prose is modified without a formal conflict.
3. **True Document Grounding (Phase 3):** Separates four distinct states (`quoteExists`, `claimExtracted`, `supportStatus`, and SymPy formal verification). Prevents `DocumentAnalyst` from silently inventing formulas (`2*x` or `1/3`) when a source document only mentions `x^2` without stating the result. Introduces `buildSourceContextBundle()` for relevance-scored multi-chunk selection strictly scoped to `request.sourceDocumentIds`.
4. **End-to-End Configuration Consistency & Zero-Quota Default (Phase 4):** Defaults Web UI and server routes to offline mock mode (`renderMode='mock'`, `voiceoverMode='none'`) with 0 external API calls, requires explicit confirmation (`externalApiConfirmed`) before any live Gemini or TTS invocation, and wires `renderMode`, `narrationMode`, `visualStyleId`, and `subtitlesEnabled` consistently from `LessonRequestV2` → `LessonDraft` → `ApprovedRenderArtifactV2` → `RenderManifestV2` → Remotion worker.
5. **Local Demo Security & Public Deployment Guard (Phase 5):** Preserves frictionless `localhost` (`127.0.0.1` / `::1`) operation for local demos while blocking unauthenticated non-loopback or public deployments unless `LUMINA_PUBLIC_DEPLOYMENT=true` and `LUMINA_API_AUTH_TOKEN` are configured. Enforces session/owner isolation (`ownerId`) across documents, drafts, and jobs, payload/upload limits, and pending job queue bounds (`LUMINA_MAX_PENDING_JOBS=3`).
6. **Audio Quality & Demo Truthfulness (Phase 6):** Separates `audio_presence` (stream exists) from `audible_speech` (measured via FFmpeg `volumedetect`), labels `MockTtsProvider` output as `silent_fixture`, rejects silent audio when live TTS is requested, and updates `docs/mentor-demo-v2.4.2.md` to state truthfully that the committed offline demo MP4 (`outputs/job-20261107171652-3cc5c0df/final.mp4`) contains a `-91.0 dB` silent fixture track.

## 5. Gemini Quota & Retry Budget Policy

| Parameter / Policy | Default Value | Behavior |
|---|---|---|
| `GEMINI_MAX_REQUESTS_PER_JOB` | `4` (`curriculum_planning`: max `2`, `narration_planning`: max `2`) | Hard ceiling on Gemini text generation calls per job/draft. Exceeding throws `gemini_budget_exceeded`. |
| `GEMINI_TTS_MAX_REQUESTS_PER_JOB` | `5` (`tts`: max `5`) | Hard ceiling on Gemini TTS calls per render job. Exceeding throws `gemini_budget_exceeded`. |
| `429 RESOURCE_EXHAUSTED` | `0` retries (Fail Fast) | Throws `gemini_quota_exceeded` immediately to protect Free Tier quota; surfaces `Retry-After` if present. |
| `401` / `403` | `0` retries (Fail Fast) | Throws `gemini_authentication_failed` / `gemini_permission_denied` immediately. |
| `404` | `0` retries (Fail Fast) | Throws `gemini_model_not_found` immediately. |
| `500` / `502` / `503` / `504` / Network | Max `1` retry (`2` attempts total, bounded by budget) | Waits `Retry-After` or exponential backoff (`1000ms * 2^attempt + jitter`). |
| Secret Redaction | Always enabled | `redactSecrets()` strips `AIza...` keys, `key=...` query params, and `Bearer ...` tokens from logs/errors. |

## 6. Mathematical Statement Consistency Model

SymPy formally verifies mathematical expressions (`expectedExpression` against `MathVisualizationSpecV2` and `validatorKey`). Because natural-language prose cannot be proven by a CAS alone, LuminaLearn V2.4.3 enforces a three-tier consistency model:

1. **Canonical Statement Generation (`canonicalStatement`):** Every verified claim receives a deterministic Vietnamese statement generated directly from the SymPy-verified `validatorKey`, `expectedExpression`, and `mathSpec` (e.g., `"Đạo hàm của hàm số f(x) = x^2 là 2*x"` or `"Tích phân xác định của hàm số f(x) = x^2 trên đoạn [0, 1] bằng 1/3"`).
2. **Statement Classification (`statementVerification`):**
   - `formal_match`: The teacher/AI `statement` matches the canonical template and verified expression with no conflicting tokens.
   - `prose_unverified`: The `statement` uses custom pedagogical phrasing without contradicting the verified expression. Status becomes `needs_review`, and approval is blocked until the teacher checks `humanSemanticReviewConfirmed = true`.
   - `conflict_detected`: The `statement`, narration `text`, `subtitleText`, or storyboard `mathExpression` contains a mathematical expression or keyword that contradicts `expectedExpression` (e.g., `3x` when `expectedExpression='2*x'`, `1/2` when `expectedExpression='1/3'`, or `h -> 1` when `h -> 0`). Status becomes `failed` and approval is strictly rejected.

## 7. Document Grounding Truth Model

Every `GroundingEvidence` item tracks four orthogonal properties:

| Property | Meaning | How Verified |
|---|---|---|
| `quoteExists` (`evidenceFound`) | Does `exactQuote` appear verbatim in the uploaded document chunk? | Exact normalized substring match in `DocumentGroundingService.verifyQuoteInDocument()`. |
| `claimExtracted` | Does the verbatim quote explicitly state a mathematical claim/formula? | `DocumentGroundingService.verifyClaimSupportInQuote()` checks explicit expression tokens without fallback invention. |
| `supportStatus` | `'supported'` \| `'needs_review'` \| `'unsupported'` | `'supported'` only when `quoteExists && claimExtracted` and expression matches; `'needs_review'` when quote only mentions `x^2` without stating the derivative/integral result; `'unsupported'` when quote states a conflicting expression. |
| `verificationStatus` (on `VerifiedClaim`) | Is the extracted claim mathematically true? | Decided exclusively by SymPy (`MathVerificationService.verifyClaims()`). |

## 9. Local Demo Security & Public Deployment Warnings

- **Localhost Mode (Default):** Requests originating from loopback (`127.0.0.1`, `::1`, `localhost`) without non-loopback `X-Forwarded-For` headers work out-of-the-box using an isolated session ID (`x-lumina-session-id` header or `lumina_session_id` cookie, defaulting to `local-dev-session`).
- **Public Deployment Guard:** Any request from a non-loopback address or when `LUMINA_PUBLIC_DEPLOYMENT=true` requires `LUMINA_API_AUTH_TOKEN` via `Authorization: Bearer <token>` or `x-lumina-api-token`. If `LUMINA_PUBLIC_DEPLOYMENT` is not enabled, non-loopback requests are rejected with `403 local_only_endpoint`.
- **Resource Ownership (`ownerId`):** Documents, lesson drafts, and render jobs are bound to the caller's `ownerId`. Cross-session reads or mutations return `403 forbidden_resource_owner`.
- **DoS & Quota Protection:**
  - JSON payloads > `256 KB` are rejected with `413 payload_too_large`.
  - Document uploads > `10 MB` are rejected with `413 file_too_large`.
  - Active/pending render jobs are capped at `LUMINA_MAX_PENDING_JOBS=3` (`429 job_queue_full`).
  - Live Gemini / TTS modes require `externalApiConfirmed: true` (`400 external_api_confirmation_required`).

## 14. Known Remaining Limitations

1. **Formal Proof Scope:** SymPy formally proves symbolic expressions (`expectedExpression`) and checks consistency against canonical statements and formula tokens in prose/narration/subtitles, but arbitrary natural-language metaphors outside mathematical expressions still require teacher semantic confirmation (`humanSemanticReviewConfirmed`).
2. **Document Extraction Heuristics:** Offline `DocumentAnalyst` deterministic extraction targets polynomial derivatives and Riemann/definite integrals; broader calculus/linear algebra document extraction in live mode relies on Gemini structured output verified against verbatim quotes and SymPy.
3. **In-Memory Session/Job Store Indexing:** While drafts and artifacts persist atomically to `outputs/.drafts` and `outputs/.artifacts` and jobs persist to `outputs/<jobId>/job.json`, the active pending queue count is tracked per Node.js server process.
