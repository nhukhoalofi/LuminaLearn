## 1. Executive Summary & Verdict

LuminaLearn V2.4.7 delivers a comprehensive reliability, concurrency, and approval safety patch on top of the V2.4.6 milestone. This update addresses critical race conditions, optimistic version precondition policies, queue capacity edge cases, and test assertions without altering existing mathematical verification, document grounding, or media rendering pipelines.

Key accomplishments:
- **Zero TOCTOU External API Bypass:** External API consent (`x-lumina-confirm-external-api` or body confirmation) is now validated strictly inside the per-draft mutation lock against the latest authoritative draft state. Concurrent mutations can no longer sneak unconfirmed live calls past approval.
- **Strict Version Precondition Policy:** `PATCH /api/lessons/[lessonId]/draft` enforces positive integer `expectedVersion`, returning HTTP 400 for missing/invalid versions and HTTP 409 for stale versions with the authoritative current version. The UI refreshes draft versions without clobbering unsaved teacher edits.
- **Decoupled Approval & Queue Consistency:** Draft approval and render queue enqueueing are completely decoupled. If the render queue is full (HTTP 429), the draft remains permanently approved (`approved: true`, `status: 'approved'`), and teachers can retry enqueueing idempotently once capacity frees up.
- **Idempotent Approval Conflict Detection:** Submitting approval with altered configuration or content throws `DraftApprovalConflictError` (HTTP 409), preventing silent overwrites of approved render artifacts.
- **Accurate E2E Acceptance & Range Assertions:** HTTP 206 partial content assertions verify exact byte counts (`Content-Length: 1024`, `Content-Range: bytes 0-1023/<total>`). Fast Chromium Playwright suites test file uploads for Markdown and scanned image PDF OCR warnings.

## 3. Checkpoint A: Gemini Consent TOCTOU Hardening

### The Vulnerability Addressed
Prior to V2.4.7, external API consent checks could run before acquiring the per-draft mutation lock. If a concurrent PATCH mutation switched the draft to `gemini_tts` or `live` render mode while an approval request was in-flight, the approval might proceed without teacher consent, potentially incurring unexpected quota consumption.

### Architectural Solution
1. `LessonDraftManager.approveDraft` and `approveDraftWithUpdates` now accept a `validateConsent?: (draft: LessonDraft) => void | Promise<void>` option.
2. The callback is executed **strictly inside `withDraftMutationLock`** after acquiring the mutex and after candidate updates are staged.
3. If consent validation throws `SecurityError(400, 'external_api_confirmation_required')`, the draft manager catches the error, restores the exact prior draft snapshot (`restoreDraftSnapshot`), and re-throws.
4. Pre-existing draft configuration is also checked: if a draft already has `narrationMode: 'gemini_tts'` or `renderMode: 'live'`, empty-body approvals must also carry explicit consent.

## 4. Checkpoint B: Safe Optimistic Concurrency & Draft Versioning Policy

### Policy Definition
- **Updates (`PATCH /api/lessons/[lessonId]/draft`):**
  - `expectedVersion` is **strictly required**.
  - Missing `expectedVersion`: returns HTTP 400 (`missing_expected_version`).
  - Invalid `expectedVersion` (non-integer, <= 0, string, null): returns HTTP 400 (`invalid_expected_version`).
  - Stale `expectedVersion` (!== current `draft.version`): returns HTTP 409 (`draft_version_conflict`) with `currentVersion`.
- **Approvals (`POST /api/lessons/[lessonId]/approve`):**
  - Empty-body approval or approvals without configuration updates preserve backward compatibility.
  - Approvals with configuration updates (`renderMode`, `narrationMode`, `visualStyleId`, `subtitlesEnabled`) **require** `expectedVersion` (HTTP 400 `missing_expected_version`).
  - Stale `expectedVersion` returns HTTP 409 (`draft_version_conflict`).
- **UI Conflict Handling (`CreateVideoForm.tsx`):**
  - When receiving HTTP 409, the component updates `draft.version = data.currentVersion` while strictly preserving teacher-entered text in local form state (`topic`, `documentText`, narration customisations).
  - Displays a clear Vietnamese notice: *"Xung đột phiên bản: Bản thảo đã được cập nhật ở nơi khác (phiên bản máy chủ: vN). Đã cập nhật phiên bản, vui lòng nhấn Lưu lại / Duyệt lại."*

## 5. Checkpoint C: Approval & Render Queue Consistency

### Enqueue Decoupling & Queue Capacity Protection
1. **Approval Separation:** Once a draft satisfies formal mathematical verification, narration checks, and teacher consent, it transitions to `status: 'approved'` and generates an immutable `ApprovedRenderArtifactV2` persisted atomically to disk.
2. **Queue Saturation (HTTP 429):** If `createV2JobFromArtifact` fails due to `job_queue_full` (exceeding `MAX_PENDING_JOBS`), the draft approval is **not rolled back**. The route responds with:
   ```json
   {
     "success": false,
     "error": "job_queue_full",
     "message": "...",
     "draftId": "draft_...",
     "artifactId": "art_...",
     "status": "approved",
     "approved": true,
     "currentVersion": 2,
     "renderConfig": { ... },
     "enqueueFailed": true
   }
   ```
3. **Idempotent Retry:** When the teacher retries after jobs drain, the endpoint detects that the draft is already approved and enqueues the job without creating duplicate or conflicting artifacts.
4. **Artifact Authorization Check:** `createV2JobFromArtifact` explicitly verifies `isArtifactCurrentlyApproved(artifact)`. Tampered, revoked, or stale artifacts are rejected with HTTP 403 (`artifact_unauthorized`).

## 6. Checkpoint D: Idempotent Approval & Configuration Conflict Detection

1. **Identical Re-approval:** If an already-approved draft receives an approval request with identical configuration, the manager returns the existing approved draft idempotently without creating a new artifact or mutating version.
2. **Conflicting Re-approval (`DraftApprovalConflictError`):** If an approval request attempts to change `visualStyleId`, `narrationMode`, `renderMode`, `subtitlesEnabled`, or core mathematical content on an already-approved draft, the manager throws `DraftApprovalConflictError` (`approved_draft_configuration_conflict`), returning HTTP 409.
3. **Invalidation via Explicit Edit:** Teachers who wish to modify an approved draft must submit `PATCH /api/lessons/[lessonId]/draft`. Any mutation invalidates the approved status (`status -> 'reviewing'`, `approvedArtifact -> undefined`, version incremented), requiring fresh SymPy verification and re-approval.

## 13. Concurrency Lock Architecture Analysis

The per-draft mutation lock (`withDraftMutationLock`) uses a chained promise queue pattern per `draftId`:
- Enforces FIFO execution order for conflicting concurrent requests.
- Guards draft snapshot rollback upon any error.
- Ensures atomic transitions for `draft.version` increments and status updates.
- Prevents race conditions between browser tabs or automated agents.
