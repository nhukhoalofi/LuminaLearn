## 1. Kết luận điều hành

P0 vertical slice cho chủ đề **“Perceptron và nguyên lý hoạt động của mạng nơ-ron nhân tạo”** đạt **GO có giới hạn**:

`Web thật → V3 draft bền vững → teacher semantic review → explicit approval → immutable artifact V3 → authorized queue → dynamic Remotion composition → MP4 35 giây + SRT`

Luồng này đã được chạy bằng Chromium và API thật, không mock HTTP/render. Không gọi Gemini hoặc TTS live. V2 được giữ nguyên và toàn bộ hồi quy V2 hiện có vẫn qua.

P1 chưa hoàn tất: audio/TTS V3, algebraic identities và source-document UX V3 đầy đủ. Vì vậy đây không phải GO cho mọi chủ đề hoặc production public deployment.

## 2. Audit baseline và lỗi tái hiện

Phase 1 cung cấp domain/capability registry, fail-closed topic routing và V2 concurrency. Phase 2 cung cấp V3 educational contracts, fixtures và Remotion scenes nhưng chưa có application workflow V3.

Các lỗi xác nhận từ baseline:

1. `EducationalPlannerV3.planLesson()` bắt mọi lỗi Live AI rồi âm thầm tạo deterministic fixture.
2. `KnowledgeValidationServiceV3` có thể gọi V2 verifier thiếu `MathSpec`, khiến canonical `x²` trở thành ngầm định; đồng thời chỉ đọc raw `passed` thay vì mapped claim status.
3. Source grounding tin `evidenceFound=true` và quote không rỗng do phía gọi cung cấp.
4. Attention chấp nhận row sum sai tới ±0,15; gradient steps chỉ kiểm tra finite; neural edges chưa kiểm tra node/direction/duplicate.
5. Renderer dùng `as any` và generic fallback ở nhánh `default`.
6. V3 chỉ có fixture composition ID, chưa có draft/approval/artifact/job/UI application path.
7. Khi chạy E2E lần đầu, queue tái hiện lỗi `queued -> rendering_remotion`; lần kế tiếp tái hiện `spawn EINVAL` do `execFile("pnpm.cmd")` trên Windows. Cả hai đều được sửa và chạy lại bằng E2E thật.

## 3. Live/Mock separation

- Plan có provenance bắt buộc: `deterministic_mock` hoặc `ai_generated_live`.
- Lỗi Live được bọc trong `EducationalGenerationError` với provenance `generation_failed`, giữ nguyên provider error code/cause.
- Live bắt buộc `externalApiConsent=true` trước khi provider được gọi.
- Test fake provider bao phủ: model unavailable, quota exhausted, invalid JSON, timeout và permission denied; không trường hợp nào fallback.
- Mock không khởi tạo live provider và chạy hoàn toàn offline.
- UI hiển thị rõ deterministic fixture, không dùng nhãn Gemini cho mock content.

## 4. Knowledge validation và source grounding

- Derivative/Riemann formal verification bắt buộc có `MathSpec` cụ thể; thiếu spec chuyển sang `human_review_required`, không dùng canonical polynomial.
- Kết quả `formally_verified` chỉ được cấp khi cả SymPy check và mapped `VerifiedClaim.verificationStatus === verified` đều đạt.
- Mỗi proof record liên kết claim ID, exact expression, canonical MathSpec, assumptions và verifier implementation.
- Contradictory prose và altered result tiếp tục bị V2 semantic/SymPy gate từ chối.
- `source_grounded` chỉ được cấp qua callback authoritative `verifySourceEvidence`; raw `evidenceFound`, document ID hoặc quote do client tự khai không có quyền chứng minh.
- Schema kiểm tra validation report ánh xạ đúng một lần cho toàn bộ claims, evidence/scene chỉ tham chiếu claim tồn tại, storyboard/report phải cùng lesson ID.
- Teacher approval được lưu riêng và không biến thành formal proof hoặc source proof.

Giới hạn: V3 Teacher Studio hiện là topic-prompt workflow. Document ownership/ingestion V2 vẫn hoạt động, nhưng chưa có UI/route V3 source-document hoàn chỉnh để inject authoritative document verifier. Vì vậy source-document V3 được đánh dấu P1/P4 tiếp theo, không tuyên bố E2E hoàn tất.

## 5. Numerical Visual DSL

### Attention

- Matrix phải vuông theo số token, finite và trong `[0,1]`.
- Row sum dùng tolerance `1e-6`.
- `highlightTokenIndex` bị chặn theo số token thật.
- Optional `scoreMatrix` dùng stable softmax (`exp(score-max)`) và đối chiếu từng trọng số.
- `isIllustrative` tiếp tục phân biệt ví dụ sư phạm với computation thật.

### Gradient descent

Với `L(w)=a(w-w*)²+L*`, schema kiểm tra từng loss, gradient `2a(w-w*)` và bước kế `w - learningRate×gradient` ở tolerance `1e-8`. Renderer tự suy ra viewport từ dữ liệu đã kiểm định để không clip ví dụ bounded hợp lệ.

### Neural architecture

- Cấm duplicate layer ID, reverse/non-adjacent edge, impossible node reference và input dimension mismatch.
- `signalMode=signal_flow_illustration` ghi đúng bản chất animation.
- `computed_forward_pass` bắt buộc computed outputs và tự tính linear/sigmoid/ReLU/step outputs để đối chiếu.

### Dispatch/safety

- Bỏ `as any`; dispatch theo discriminated `visualPayload.sceneType`.
- Scene type và payload type phải khớp chính xác.
- Unsupported payload ném lỗi thay vì generic fallback.
- Generic text dùng `NoExecutableString`; không nhận script/import/exec payload.

## 6. V3 draft lifecycle

`LessonDraftManagerV3` cung cấp:

- trạng thái draft/review/approval cùng job states queued/rendering/completed/failed;
- owner binding;
- durable JSON persistence bằng temporary file + atomic rename;
- per-draft mutex và optimistic `expectedVersion`;
- edit title, objectives, claim statements, narration, subtitles và typed visual payload;
- mọi edit tăng version, chạy validation lại, xóa semantic confirmation và thu hồi artifact cũ;
- frontend không có trường sửa verification/proof;
- stale tab trả HTTP 409 và UI yêu cầu reload.

## 7. ApprovedRenderArtifactV3

Artifact V3 là trusted server snapshot gồm exact request, lesson plan, claims, validation report, source evidence nằm trong plan, storyboard/typed payloads, render settings, teacher approval, owner, draft/version và provenance.

- Canonical JSON keys được sắp xếp ổn định.
- SHA-256 do server tính; được mô tả là integrity hash, không phải chữ ký số.
- Schema và hash được kiểm tra khi enqueue và ngay trước render.
- Authorization kiểm tra riêng với draft hiện tại; hash đúng không thay thế owner/version authorization.
- Callback authorization chạy lại trước khi bắt đầu Remotion.
- Tampering và stale/superseded artifact bị test từ chối.

## 8. Job processing và renderer

- Job store nhận riêng `ApprovedRenderArtifactV3`; không nhận arbitrary path/component/command từ client.
- Dynamic production composition ID `LuminaSceneV3` dùng approved storyboard props và `calculateMetadata` theo duration.
- Remotion-only path được phép chuyển `validating -> rendering_remotion`; V2 Manim path giữ nguyên.
- Windows gọi trực tiếp Remotion CLI qua `process.execPath`, fixed CLI path và fixed argument array, không shell interpolation.
- Idempotency theo artifact ID + owner; queue capacity dùng guard hiện có.
- SRT được tạo từ cùng authoritative storyboard timeline với burned-in subtitles.
- `narrationMode != none` fail rõ `v3_audio_not_implemented`, không silent provider switch.

## 9. Teacher Studio UI và API

Các route mới:

- `POST /api/v3/lessons/draft`
- `GET/PATCH /api/v3/lessons/:lessonId/draft`
- `POST /api/v3/lessons/:lessonId/review`
- `POST /api/v3/lessons/:lessonId/approve`

UI hỗ trợ chọn AI, Mock/Live, nhập topic, xem provenance/claims/status/storyboard, sửa title/objectives/claims/narration/subtitles/visual JSON, semantic review, approve, theo dõi job, xem/tải MP4 và tải SRT. Proof status không editable. Planning-only topics không thể approve/render.

## 13. Security và backward compatibility

- Không thay đổi V2 endpoints/artifact schema/pipeline semantics.
- Public/local authorization guard hiện có được tái sử dụng; owner không lấy từ client header.
- Không model-generated code execution, arbitrary filesystem path hoặc arbitrary composition ID.
- Không secret trong artifact/log/UI.
- Live consent được kiểm tra trước provider construction/call ở route.
- Không Gemini/TTS API call, không commit/push/merge/deploy.

## 14. Hạng mục còn thiếu

1. P1 V3 audio: provided audio authorization và Gemini/Google TTS wiring vào V3 artifact/timeline; hiện chỉ `none` được render.
2. V3 source-document application path hoàn chỉnh (upload/ownership → authoritative evidence callback → V3 draft UI).
3. Algebraic identity capability cho “7 hằng đẳng thức đáng nhớ”.
4. Gradient Descent và Self-Attention vẫn `planning_only`; numerical payloads được kiểm định nhưng production approval bị chặn.
5. Durable multi-process/database locking chưa có; mutex hiện bảo vệ trong một Node process và file/version bảo vệ restart.
6. Public multi-user authentication vẫn là single configured bearer-token identity, chưa phải hệ thống tài khoản/role.
7. Zod/Remotion major-version alignment cần một migration riêng.

## 15. GO/NO-GO và Phase 4 đề xuất

- **GO:** offline local-demo P0 Perceptron vertical slice và tiếp tục mentor demo bằng `narrationMode=none`.
- **NO-GO:** public production, V3 live Gemini/TTS, hoặc tuyên bố mọi AI/Math topic render-ready.

Phase 4 nên ưu tiên: V3 source-document authority integration; durable shared repository/lock; audio timeline/TTS opt-in; Zod migration; algebraic identity verifier/scene; sau đó mới nâng Gradient/Attention lên render-ready bằng E2E video QA riêng.
