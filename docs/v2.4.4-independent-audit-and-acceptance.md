## Reproduced defects and fixes

### A. SymPy claim-key collision

`BaseSymPyVerifier` built a JavaScript object keyed only by `validatorKey`; a later claim replaced an earlier claim before the Python subprocess saw it. Mapping the result back through the same key allowed two independent claims to inherit one result.

Policy selected: duplicate claim IDs or duplicate `validatorKey` values are rejected for the complete formal-verification batch, including identical expressions. There is no silent deduplication. The check exists both at the real verifier boundary and `MathVerificationService`. `verifyArtifactIntegrity()` also rejects legacy artifacts with duplicate formal keys even if their integrity hashes are recomputed.

Evidence:

- Real TypeScript → Python SymPy subprocess verifies the valid singleton claim.
- `[wrong, correct]` and `[correct, wrong]` both fail with `duplicate_validator_key`.
- Identical duplicate expressions fail by the documented policy.
- Existing derivative and Riemann tests remain green.
- A legacy artifact with a recomputed content hash and verification binding hash is still rejected.

Affected paths: `packages/agent/src/orchestration/math-verifier.ts`, `packages/agent/src/orchestration/draft-manager.ts`, `packages/agent/test/math-verification.test.ts`, `packages/agent/test/draft-integrity.test.ts`.

### B. Owner-ID spoofing

Client-controlled `x-lumina-owner-id` and `x-lumina-client-id` no longer select identity.

- Development/local demo uses the fixed server principal `local-single-user` and is explicitly a single-user trust domain.
- Public/shared mode derives the principal only from a credential validated against `LUMINA_API_AUTH_TOKEN` using timing-safe comparison.
- Owner headers cannot override that principal.
- Production fails closed without the public-deployment configuration and credential.
- `Host`, request URL, and forwarding headers are not authentication evidence.
- `next dev` and `next start` are loopback-bound by their package scripts. A production-style local demo must explicitly opt into `LUMINA_LOCAL_DEMO=true`.

Tests prove forged owner headers do not change the principal and invalid public credentials are rejected. This is **not** a claim of multi-user authentication or isolation: one configured API token represents one public principal.

Affected paths: `apps/web/src/server/security.ts`, `apps/web/test/security.test.ts`, `apps/web/package.json`, `.env.example`.

### C. Durable document ownership

The in-memory owner `Map` was replaced with an atomic `ownership.json` record stored beside document metadata/chunks. Document IDs and owner records are validated. Ownership is loaded and authorized before chunks are reloaded. Missing, malformed, or conflicting metadata fails closed; an unknown owner is never treated as public.

The restart test uses real temporary files, a fresh `DocumentOwnershipRepository`, and a fresh `DocumentStore`: owner B is denied, owner A succeeds, and missing/corrupt metadata is denied. Legacy documents without ownership metadata are intentionally denied and must be re-uploaded in the local demo.

The document GET route now enforces authentication, ownership recovery, and authorization.

Affected paths: `apps/web/src/server/document-ownership.ts`, `apps/web/src/server/v2-services.ts`, `apps/web/src/app/api/documents/route.ts`, `apps/web/src/app/api/documents/[documentId]/route.ts`, `apps/web/src/app/api/lessons/draft/route.ts`, `apps/web/test/document-ownership.test.ts`.

### D. Grounding support enforcement

The first-claim fallback was removed. Every evidence item must name an existing claim. Exact quote location/document checks still run, then a claim-aware relation gate requires the quote to explicitly associate the operation (derivative/integral/Riemann) with the claimed result. `supportStatus !== 'supported'` is always rejected for a live plan; mentioning an expression in generated prose cannot override the result.

Regression evidence covers a valid derivative, a source-stated `3x` claim rejected by real SymPy, an invalid claim ID, a bare `x²` mention returning `needs_review`, an unrelated fraction not supporting an integral, fabricated citations, wrong documents, and relevant late chunks.

Affected paths: `packages/agent/src/orchestration/document-grounding.ts`, `packages/agent/src/orchestration/orchestrator.ts`, `packages/agent/test/grounded-provider-context.test.ts`.

### E. Recoverable semantic review

Draft creation now returns HTTP 202 with the persisted draft when the state is recoverable `needs_review`; the Web UI opens the review interface and displays both the exact statement and deterministic canonical statement. A teacher confirmation/edit triggers full SymPy reverification.

After successful confirmation, `resumeAfterSemanticReview()` creates only the missing storyboard, treatment, narration, quality review, and manifest. It does not repeat curriculum planning. The persisted Gemini text-request budget is carried forward and merged so a restart cannot reset the per-job text budget. Contradictory prose remains rejected and no partially verified artifact can be approved.

The integration test creates a fake-Gemini draft with real SymPy, restarts the manager from disk, confirms semantic review, and reaches `ready_to_render` with exactly `curriculum_planning` then `narration_planning`—no duplicated curriculum request.

Affected paths: `packages/agent/src/orchestration/orchestrator.ts`, `packages/agent/src/orchestration/draft-manager.ts`, `apps/web/src/app/api/lessons/draft/route.ts`, `apps/web/src/components/CreateVideoForm.tsx`, `packages/agent/test/grounded-provider-context.test.ts`.

## Gemini request-budget status

Existing and newly exercised tests cover single curriculum/narration attempts, structured-output revision, transient 503 retry, fail-fast 401/403/429, TTS sequencing, and TTS budget exhaustion. Semantic-review resume now preserves the prior per-job text count across restart.

Remaining limitation: budgets are per job/process. `LUMINA_MAX_PENDING_JOBS` bounds render jobs, but there is no process-independent, project-wide Gemini RPM/RPD limiter for concurrent draft requests or multiple server replicas. Google-side quota remains authoritative. Therefore project-level quota protection is not claimed.

## Acceptance and deployment decision

- Formal verification soundness for duplicate keys: **PASS**.
- Owner-header spoofing prevention: **PASS** for the implemented single-user/token model.
- Ownership durability/restart fail-closed behavior: **PASS**.
- Grounding association and unsupported evidence rejection: **PASS**.
- Recoverable `needs_review`: **PASS** at package/API integration level.
- Gemini Live/TTS: **NOT TESTED**; zero live calls.
- Offline mentor demo: **GO**, with manual frame QA explicitly pending and fixture audio labeled truthfully.
- Public/shared deployment: **NO-GO** until a trusted multi-user identity/session system and project-wide distributed rate limiting are implemented and browser E2E is run.

## Remaining security and release limitations

1. Public auth is a single server-configured bearer token, not a user/session identity system.
2. Local demo authorization assumes the loopback-bound process and machine account are trusted.
3. Gemini quotas are bounded per job but not globally coordinated across processes/replicas.
4. Browser automation was unavailable; only API/package integration is proven.
5. The existing video still requires a real reviewer to complete manual frame QA.
6. The Remotion/Zod version warning should be resolved in a separate dependency-compatibility change before a public release.
