## 4. Universal Visual Engine architecture

The implemented path is:

`typed scientific data → pedagogical visual intent → capability resolver → scientific adapter → motion recipe → Remotion composition → generated QA evidence`

Renderer selection in `resolveVisualCapabilityV1` receives no topic name. It evaluates the scientific data kind, visual intent, scene type, validation evidence, real adapter readiness, and duration limits. Unsupported combinations return a structured `needs_review` or `unsupported` finding.

The Universal Educational Director now extracts typed scientific data and invokes this resolver. It does not select Gradient Descent, derivative, or algebra components by benchmark name. Presentation-only concept/summary scenes can still use safe infographic mappings; scientific scenes without typed evidence fail closed.

## 6. Implemented adapters and engines

- Formula Engine: multi-step KaTeX layout, step reveal, semantic term highlighting, worked-example progression, and proof/claim references.
- Graph Engine: bounded polynomial/quadratic/sine/exponential evaluation, exact curve sampling, markers from the same function, correct analytical tangent, and an illustrative secant that converges to the tangent.
- Optimization Engine: frame state is derived from the validated quadratic at every frame. Interpolated positions are explicitly visual transitions, not claimed iterations.
- Diagram Engine: typed directed nodes and edges; no fixed neural architecture embedded in the adapter.
- Attention adapter: preserves the supplied normalized matrix values exactly.
- Three style foundations: Math Chalkboard, AI Data Story, and Systems Whiteboard, with background, typography, color semantics, easing, transition behavior, camera grammar, and subtitle safe area.

## 7. Adapters not implemented

- General 2D geometry renderer and R06 area-preserving transformation compiler.
- Probability-tree renderer with probability-conservation QA.
- R09 semantic camera compiler. Camera grammar is registered but intentionally not declared implemented.
- Full measured-word TTS alignment is outside this sprint. Beat cues distinguish `planned` from `measured_audio` and never claim planned timing is verified speech synchronization.

## 8. Motion recipes

Implemented and tested: R01 Formula Reveal, R02 Semantic Highlight, R03 Graph Trace, R04 Parameter Motion, R05 Dynamic Tangent, R07 Information Flow, R08 Matrix/Heatmap Reveal, and R10 Worked Example Progression.

All implemented recipes are typed, deterministic, frame-driven, duration-bounded, adapter-scoped, safe-area aware, and do not mutate mathematical claims.

## 13. Remaining limitations and risks

- Latest baseline CI is red, and the uncommitted candidate cannot have a successful candidate-commit CI run.
- Geometry and probability adapters are deliberately incomplete.
- The derivative demo validates the reusable secant/tangent mechanism, but a broader fixture matrix for several tangent positions should be added in Sprint C.
- Render evidence consists of frame sequences/contact sheets, not three encoded acceptance MP4 files.
- Remotion/Zod major-version mismatch remains a packaging risk despite successful local renders.
- Human approval, proof bindings, content hashes, and artifact version authorization were not bypassed; the Sprint B fixtures are QA fixtures, not newly approved teacher artifacts.
