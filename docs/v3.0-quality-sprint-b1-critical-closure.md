## 2. CI TypeScript TS1360 Fix & Root Cause

### Root Cause
In GitHub Actions run `42943258245`, `packages/scene-schema/src/v3/visual-dsl.ts:648` failed with:
```
error TS1360: Type '{ formula_step: ...; ... }' is missing the following properties from type 'Record<VisualElementV3["elementType"], VisualPrimitiveReadinessV3>': segment, polygon
```

The discriminated union `VisualElementV3` was expanded in Sprint B to introduce `segment` and `polygon` primitives, but the readiness table `VISUAL_PRIMITIVE_READINESS_V3` had not registered them, violating TypeScript's exhaustive `satisfies Record<VisualElementV3['elementType'], ...>` check.

### Solution
Synchronized `VISUAL_PRIMITIVE_READINESS_V3` with:
- `segment: 'preview_ready'`
- `polygon: 'preview_ready'`

Both primitives are marked `preview_ready` because the SVG rendering adapters and scene components exist, but formal end-to-end visual test suites have not been executed in this sprint.

## 3. Scientific Verification Authority Redesign

### The Vulnerability
Prior to Sprint B.1, client payloads or planner heuristics could inject `validation: 'deterministic_numeric'` or declare `isVerified: true` without server-side verification, bypassing SymPy claim checking. Furthermore, `scientificDataForScene` synthesized `proofReferenceId: 'proof_${claims[0].id}'` even for claims lacking formal mathematical proofs.

### Architectural Redesign
1. **Mathematical Refinement in `OptimizationTraceDataV1Schema` (`packages/scene-schema/src/v3/visual-engine.ts`):**
   - Added a Zod `superRefine` block verifying:
     - Steps are strictly monotonically increasing (`stepNumber[i] < stepNumber[i+1]`).
     - Numeric values are finite and non-NaN.
     - For quadratic loss $L(w) = a(w - w^*)^2 + c$, verifies that $L(w)$ matches the loss within $\epsilon = 10^{-4}$.
     - Gradient matches the exact derivative $L'(w) = 2a(w - w^*)$ within $\epsilon = 10^{-4}$.
     - Parameter update step strictly follows $w_{t+1} = w_t - \eta \nabla L(w_t)$ within $\epsilon = 10^{-4}$.
2. **Authority Decoupling in `universal-educational-director-v3.ts`:**
   - Multi-claim status aggregation is strictly fail-closed: if any claim is unverified or requires human review, the aggregated status cannot be `verified`.
   - `proofReferenceId` is ONLY emitted if the claim has `verificationResult.status === 'verified'` and carries a non-empty `formalProofSummary`.
   - `deterministic_numeric` is only awarded to visual direction if claims are actively backed by numerical/formal verification.

## 5. Probability Tree Topology Fix

### The Defect
In `packages/animation/src/educational/scientific-visual-adapters-v3.ts`, `adaptProbabilityTreeV3` generated `neural_connection` elements linking parent and child nodes. However, the connection `fromNode` was hardcoded to `0`:
```typescript
// Buggy implementation:
fromNode: 0,
toNode: nodePositions.get(child.id) ?? 0,
```
In multi-level probability trees (e.g. Bayes theorem, decision trees), every branch incorrectly originated from the root node rather than the true parent.

### The Fix
Introduced a parent-index lookup via the node position map:
```typescript
const fromNodeIndex = nodePositions.get(parent.id) ?? 0;
const toNodeIndex = nodePositions.get(child.id) ?? 0;
// Generates neural_connection linking fromNodeIndex -> toNodeIndex
```
The tree topology now renders correctly across arbitrary branching depth.

## 6. Attention Matrix Rendering & Constraint Alignment

### The Inconsistency
- `AttentionMatrixDataV1Schema` in `visual-engine.ts` allowed up to 12 tokens/weights (`max(12)`).
- `VisualMatrixElementSchema` in `visual-dsl.ts` enforced a mobile viewport boundary of `max(8)`.
- Furthermore, `VisualDslSceneV3.tsx` only rendered matrix grid cells without token headers (`colLabels`, `rowLabels`), making self-attention attention weights uninterpretable to learners.

### The Fix
1. Harmonized `AttentionMatrixDataV1Schema` to `max(8)` tokens and `max(8)` rows.
2. In `VisualDslSceneV3.tsx`:
   - Rendered horizontal column token labels across the top axis with responsive font scaling and safe text clipping.
   - Rendered vertical row token labels along the left axis.
   - Preserved mobile 9:16 portrait readability within the bounded 720×1280 composition.

## 8. Geometry Rendering Isometric Fix

### The Problem
`VisualDslSceneV3.tsx` rendered 2D geometry primitives (`point`, `line`, `segment`, `polygon`) using independent, anisotropic normalized scaling for X and Y axes. On 9:16 mobile canvas (720×1280), a square coordinate grid $([-5, 5] \times [-5, 5])$ was stretched vertically by $1280/720 \approx 1.77\times$, turning circles into tall ellipses, right angles into obtuse/acute angles, and squares into rectangles.

### The Fix
Implemented isotropic 1:1 aspect ratio coordinate scaling:
- Calculated uniform scale factor $S = \min(\text{plotWidth} / \Delta x, \text{plotHeight} / \Delta y)$.
- Centered the isometric viewport within the available canvas area.
- All geometric shapes, right angles, and euclidean distances now render with undistorted metric fidelity.

## 9. Web Security CI Isolation Fix

### Root Cause
GitHub Actions CI workflow (`.github/workflows/ci.yml`) exports `LUMINA_LOCAL_DEMO: 'true'` at the job environment level. In `apps/web/test/security.test.ts`, tests switching to public mode (`LUMINA_PUBLIC_DEPLOYMENT = 'true'`) failed because `resolveDeploymentMode()` detects conflicting flags and throws:
```
SecurityError: 500 unsafe_deployment_configuration: local demo and public deployment flags cannot both be enabled.
```

### The Fix
In all security tests involving public deployment:
1. Captured initial `origLocal = process.env.LUMINA_LOCAL_DEMO`.
2. Explicitly `delete process.env.LUMINA_LOCAL_DEMO` when entering public deployment test branches.
3. Restored `process.env.LUMINA_LOCAL_DEMO` in `finally` blocks.
