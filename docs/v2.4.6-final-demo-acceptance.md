## 2. All Completed Source Changes

### Phase 1 — Draft Identity & Concurrency Hardening
- **Cryptographically Unique Draft Identity:** Replaced predictable `draft_${requestId}` with `draft_${randomUUID().replace(/-/g, '')}`, decoupling external correlation IDs (`requestId`) from durable draft IDs and file paths. Added regex validation (`/^draft_[a-zA-Z0-9_-]{8,120}$/`) and hard-link (`linkSync`) create-if-absent semantics to prevent path traversal and file overwrites.
- **Per-Draft Mutation Locking:** Introduced `withDraftMutationLock(draftId, operation)` in `LessonDraftManager`, serializing `updateDraft`, `approveDraft`, `approveDraftWithUpdates`, and `rejectDraft` per draft.
- **Stale Version Conflict Detection:** Added `DraftVersionConflictError` (`draft_version_conflict`) and `expectedVersion` parameter to `updateDraft`, `approveDraft`, and `rejectDraft`. The API route returns HTTP 409 when the client version is stale.
- **Atomic Approval with Proposed Updates:** Created `approveDraftWithUpdates(draftId, updates, note, options)` which atomically applies configuration updates and approves the draft within the same mutation lock. If validation or approval fails, the prior draft state is restored immediately.
- **Idempotent Approvals:** Repeated approval calls on an already-approved draft return the existing snapshot without re-rendering or creating conflicting artifacts.
- **Zod Schema & API Protection:** Strict schema parsing in `readApprovalRequest` with `expectedVersion`. Pre-mutation external API consent checking via `assertApprovalExternalApiConsent`.

### Phase 2 — Request Budget & In-Flight State Preservation
- **In-Flight Attempt Recovery:** Updated `GeminiRequestBudget` to conservatively retain attempts in `started` state across restart hydration without resetting attempt counters or causing quota overdraft.
- **Monotonic Attempt Accounting:** Verified that concurrent retry operations share the same budget instance and persist attempts monotonically without duplicate consumption.

### Phase 3 — Real Browser End-to-End Suite (Playwright)
- Configured Playwright 1.65.0 with Desktop Chromium in `apps/web/playwright.config.ts`.
- Implemented `apps/web/e2e/teacher-workflow.spec.ts` (fast browser suite): verifies SymPy mathematical rejection (e.g. `999*x`), successful correction (`2*x`), teacher review controls, grounded document extraction, and local storage recovery.

### Phase 4 — Gemini TTS Offline Preflight

- Validated model selection (`gemini-3.8-flash-lite-tts`), voice (`Kore`), language (`vi`), FFmpeg, and FFprobe availability with 0 external API calls made.

## 7. Known Remaining Limitations & Next Recommended Milestones

1. **Multi-Replica Draft Concurrency:** `withDraftMutationLock` operates per-process in Node.js memory. For horizontal scaling across multiple container instances, introduce Redis distributed locking or Postgres transactional state.
2. **Public Authentication:** The current public gate uses a shared bearer token (`LUMINA_API_AUTH_TOKEN`). Production multi-tenancy requires full user account and session management.
3. **Remotion Zod Compatibility:** Remotion 4.0.541 outputs a non-fatal warning recommending Zod `4.6.7` while the workspace pins Zod `3.24.1` / `3.25.76`. Both run and build successfully; a major Zod migration should be scheduled in V2.5.
4. **Authorized Visual Sign-Off:** Automated QA verifies geometry, bounding boxes, margins, and black frames. Final subjective pedagogical review remains flagged as `requires_manual_review`.
